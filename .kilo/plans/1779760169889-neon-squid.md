# Plan: Pre-Spun CPU Thread Pool Optimization

## Goal

Implement the three key optimizations learned from the rsnano head-to-head benchmark to make nano-rspow's CPU backend faster at easy/medium difficulty tiers:

1. **Pre-spun threads with busy-wait** — eliminate rayon's per-call task distribution overhead
2. **AtomicBool cancellation** — remove work-stealing coordination during search
3. **Per-thread RNG seeds from system entropy** — architectural cleanliness for dynamic thread management

## Branch Strategy

- **New branch**: `feat/cpu-pre-spun-pool` (based off `main`)
- **No rsnano dependencies** — all changes are native to nano-rspow
- **rsnano sources stay in `experiment/rsnano-head-to-head`** — not merged to main or the new branch

#### New Architecture (pre-spun threads)
```rust
pub(crate) struct CpuBackend {
    threads: Vec<JoinHandle<()>>,
    senders: Vec<mpsc::Sender<WorkCommand>>,
}

enum WorkCommand {
    Search {
        hash: [u8; 32],
        threshold: u64,
        done: Arc<AtomicBool>,
        cancel: Arc<AtomicBool>,
        result_tx: mpsc::Sender<u64>,
    },
    Stop,
}

impl CpuBackend {
    pub fn new() -> Self {
        let thread_count = std::thread::available_parallelism()
            .map(|n| n.get())
            .unwrap_or(4);
        
        let mut threads = Vec::new();
        let mut senders = Vec::new();
        
        for _ in 0..thread_count {
            let (cmd_tx, cmd_rx) = mpsc::channel::<WorkCommand>();
            senders.push(cmd_tx);
            
            threads.push(thread::spawn(move || {
                let mut rng = XorShift1024Star::new_from_system();
                
                loop {
                    let cmd = match cmd_rx.recv() {
                        Ok(cmd) => cmd,
                        Err(_) => return,
                    };
                    
                    match cmd {
                        WorkCommand::Stop => return,
                        WorkCommand::Search { hash, threshold, done, cancel, result_tx } => {
                            const BATCH: usize = 256;
                            
                            loop {
                                if done.load(Ordering::Relaxed) || cancel.load(Ordering::Relaxed) {
                                    break;
                                }
                                
                                for _ in 0..BATCH {
                                    let nonce = rng.next();
                                    if difficulty::compute(&hash, nonce) >= threshold {
                                        if !done.swap(true, Ordering::AcqRel) {
                                            let _ = result_tx.send(nonce);
                                        }
                                        break;
                                    }
                                }
                            }
                        }
                    }
                }
            }));
        }
        
        Self { threads, senders }
    }
}

impl Backend for CpuBackend {
    fn generate(&self, hash: &[u8; 32], threshold: u64, cancel: &CancelToken) -> Option<u64> {
        let done = Arc::new(AtomicBool::new(false));
        let (result_tx, result_rx) = mpsc::channel();
        
        for sender in &self.senders {
            let _ = sender.send(WorkCommand::Search {
                hash: *hash,
                threshold,
                done: Arc::clone(&done),
                cancel: Arc::clone(&cancel.flag),
                result_tx: result_tx.clone(),
            });
        }
        drop(result_tx);
        
        loop {
            match result_rx.recv_timeout(Duration::from_millis(10)) {
                Ok(nonce) => return Some(nonce),
                Err(RecvTimeoutError::Timeout) => {
                    if cancel.is_cancelled() {
                        done.store(true, Ordering::Relaxed);
                        return None;
                    }
                }
                Err(RecvTimeoutError::Disconnected) => return None,
            }
        }
    }
}

impl Drop for CpuBackend {
    fn drop(&mut self) {
        for sender in &self.senders {
            let _ = sender.send(WorkCommand::Stop);
        }
        for thread in self.threads.drain(..) {
            let _ = thread.join();
        }
    }
}
```

## Key Design Decisions

### Why `mpsc::channel` instead of `crossbeam`?

- `std::sync::mpsc` is in the standard library (no new dependencies)
- Performance is sufficient for this use case
- Avoids adding `crossbeam` as a dependency

### Why `recv_timeout(10ms)` instead of blocking `recv()`?

- Allows checking the `cancel` token periodically
- 10ms latency is acceptable for PoW cancellation
- Simpler than implementing a full `select!` mechanism

### Why eager thread spawning in `new()`?

- Matches rsnano's approach (threads are always ready)
- Eliminates first-call latency
- For benchmarks and production use, threads are always used
- Wasteful if `CpuBackend` is created but never used, but this is rare

### Why keep rayon as a dependency?

- May be used elsewhere in the codebase
- Future features might benefit from work-stealing
- Removing it is a separate refactoring task

## Risks and Mitigations

### Risk: Thread spawning overhead on cold start
- **Mitigation**: Threads are spawned once at `CpuBackend::new()`, amortized over many `generate()` calls
- **Verification**: Cold mode benchmark will show if this is an issue

### Risk: Cancellation latency (10ms polling)
- **Mitigation**: 10ms is acceptable for PoW; could be reduced to 1ms if needed
- **Verification**: Cancellation tests will confirm behavior

### Risk: Memory overhead from pre-spun threads
- **Mitigation**: Each thread uses ~1MB stack; 8 threads = 8MB, acceptable
- **Verification**: Monitor memory usage during benchmarks

### Risk: macOS M1 E-core migration (same issue as rsnano)
- **Mitigation**: This is an OS-level issue, not a code issue; pre-spun threads may still migrate
- **Verification**: Compare per-thread throughput in benchmarks; if E-core migration occurs, document it

## Future Work

- **Thread pinning**: On macOS, use `thread_policy_set(THREAD_AFFINITY_POLICY)` to pin threads to P-cores
- **Adaptive thread count**: Dynamically adjust thread count based on system load
- **Hybrid approach**: Use pre-spun threads for easy tiers, rayon for hard tiers (complex, not recommended)
